# Как работает хаб

- **Задачи — в Postgres (Supabase).** `backlog/tasks.json` — это засеянная история и резерв: если база недоступна, приложение показывает последний закоммиченный снимок. Коммит в `tasks.json` **больше не меняет** то, что видно в интерфейсе.
- **Источник правды в Git — остальное:** `content/calendar.json`, `projects/*.md`, `memory/*.md`, `agents/access.json`, `src/data/workspaces.json`. Сборка проверяет их и падает с указанием файла и номера записи.
- **Статусы задач:** `backlog`, `in_progress`, `review`, `done`. Статуса `todo` нет — используем `backlog`.
- **Исполнители:** `Claude`, `Gemini`, `Human`. Если исполнитель не указан — `Human`.
- **Описание задачи** хранится в поле `notes` (не `description`).
- **Календарь (`/schedule`):** переносы по сетке пока сохраняются только в браузере — в базу они не пишутся. Новые задачи надёжнее создавать кнопкой «Создать задачу» на `/tasks`: она пишет прямо в Postgres.
- **Доска `/tasks`** читает Postgres и умеет создавать задачи: «Создать задачу» → `POST /api/tasks`. Воркспейс не выбирается — он выводится из направления.
- **Агенты** читают задачи через `GET /api/context` (уже из базы). Запись через API для агентов пока не реализована: `POST /api/tasks` требует сессии пользователя, а не токена агента.
